# Quantum Maze 0.4.2 — Bell-in-the-Maze (varied-basis measurements)

## Goal

Close the second item in the v0.4 PhD-level critique: the maze's Bell pairs are observationally classical because both ends always measure in the Z basis. v0.4.2 makes the maze itself demonstrate non-locality — not just the side panel.

The fix is one mechanism with two surfaces:

- **A (per-event quantum behavior):** Each Bell observation picks measurement angles per side from the CHSH set. Outcomes are correlated, not always identical. Partners can disagree.
- **B (cumulative proof from gameplay):** Every maze Bell observation contributes a data point to a running S. The player drives the CHSH violation through their own movements, not a background loop.

## Background: why same-basis Bell is classical-equivalent

|Φ+⟩ measured in Z on both ends gives `{00: ½, 11: ½}` — perfect correlation, identical to a sealed-envelope scheme with a shared coin flip. No statistical test on those outcomes distinguishes quantum from classical.

Varying the angle per side gives correlation `E(a, b) = cos(2(a − b))`, which can produce CHSH `S = 2√2 ≈ 2.828`. No local hidden-variable theory can reproduce that — Bell's theorem. The maze's Bell pairs become genuinely non-classical the moment the two ends can choose different bases.

## Design Decisions

| # | Question | Decision |
|---|---|---|
| 1 | Where do the angles come from? | Canonical CHSH set. Alice ∈ {0°, 45°}, Bob ∈ {22.5°, −22.5°}. Server picks one of the four pairs uniformly per observation. |
| 2 | What does an OPEN/SOLID outcome mean now? | Each end's measurement is its own bit. `1 → OPEN`, `0 → SOLID`. Partners no longer always match. |
| 3 | Does the background CHSH trickle keep running? | Yes — keeps S converging quickly. Gameplay Bell events feed the **same** S tally, so the player sees their own observations push it past 2. |
| 4 | What about the maze's quantum-fidelity invariant (at least one wall opens)? | Bell walls have always been allowed to land SOLID; the non-zero circuit handles wall-set guarantees. Unchanged. |
| 5 | Migration of existing CHSH side panel? | Stays. New gameplay-driven S contributes to the same display. Add a "gameplay trials" counter alongside "background trials". |
| 6 | Player-visible cue for "partner disagreed"? | Yes — see Rendering. |

## Backend changes (`server.py`)

### Bell endpoint takes angles

Current:
```json
{ "type": "bell" }
```

New (both fields optional; default to 0° = current behavior):
```json
{ "type": "bell", "alice_angle_deg": 0.0, "bob_angle_deg": 22.5 }
```

Internal: collapse `build_bell` and `build_chsh` into a single function `build_bell(alice_rad, bob_rad)` with `alice_rad = bob_rad = 0` reproducing the old |Φ+⟩+Z measurement. The CHSH endpoint stays as an alias (back-compat for the existing side panel) but routes to the same builder.

### Frontend wrapper

`Quantum.bell(cellA, partnerB)` becomes `Quantum.bell(cellA, partnerB, aliceAngleDeg, bobAngleDeg)`. The maze code picks angles per call.

## Frontend changes (`maze.js`)

### Pick angles per Bell observation

In `processBell(cell)`, when triggering a Bell measurement:

```js
const ALICE_ANGLES = [0, 45];
const BOB_ANGLES = [22.5, -22.5];
const aliceAngle = ALICE_ANGLES[Math.random() < 0.5 ? 0 : 1];
const bobAngle = BOB_ANGLES[Math.random() < 0.5 ? 0 : 1];
const { a, b } = await Quantum.bell(cell, partner, aliceAngle, bobAngle);
// a controls this wall, b controls the partner wall — independent
```

The angle pair (aliceAngle, bobAngle) is recorded with the outcome so it can feed the CHSH tally.

### Wall semantics

- `a === 1 → wall OPEN`
- `a === 0 → wall SOLID`
- Same for `b` on the partner side
- Partners are still entangled, but no longer guaranteed to match. The cycle-prevention check still applies per-wall.

### Feed gameplay S

After each maze Bell observation, push `(aliceAngle, bobAngle, a, b)` into the existing `chshTally` (the same data structure the background loop uses). Bump a separate `gameplayTrials` counter.

### Visual cue for mismatch

In `drawBellThreads` and the partner-flash animation:

- **Match (a === b):** current behavior — both ends pulse the same color (cyan if OPEN, grey if SOLID).
- **Mismatch (a !== b):** partners pulse opposite colors. Brief "scissoring" effect on the thread — a single split-color pulse from one end to the other showing the disagreement traveling across the maze.

This is the visible quantum weirdness — the player sees partners disagree and learns from the surrounding text that this is the signature of non-classical correlation.

### Side panel update

`#chsh-panel` adds one line:

```
gameplay trials  3 / 18 (12%)
```

Showing what fraction of the S tally came from the player's own Bell observations. Pure narrative — the math is the same.

## Tests

### Backend

- `tests/test_server.py`: Bell endpoint accepts and uses angle params. Default (no angles) reproduces old behavior.
- `tests/test_quantum.py`: For a fixed angle pair, the empirical correlation `E(a, b)` matches `cos(2(a − b))` within statistical bounds across N trials.
- `tests/test_chsh.py`: Existing CHSH violation test still passes (the CHSH endpoint now routes to the unified builder).

### Browser invariants

- `tests/e2e_invariants.js`: New invariant — over N games with Bell observations, the partner-disagree rate is non-zero and within expected bounds (~25% averaged over the CHSH angle set, since each pair has a different correlation).

## Out of scope

- Persistent statevector across the game (the "Bell pairs are stateless triggers" item from the critique — separate concern, separate fix).
- Noise model toggle.
- Replacing the pre-picked exit with a measurement on arrival.

## Risks

1. **Loss of "partners always match" magic.** Mitigated by the new mismatch visual being its own kind of dramatic — the disagreement IS the spookiness.
2. **Player confusion about what changed.** Mitigated by a short instructional line on the panel: "Bell partners are entangled at varied angles — sometimes they disagree, and the pattern of agreements over many trials is what proves non-locality."
3. **CHSH S converges slower if gameplay events dominate.** Background trickle keeps running; gameplay just adds to it. Worst case S converges at the same rate as today.
