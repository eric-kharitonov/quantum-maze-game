# Quantum Maze 0.4 — CHSH Panel + Wavefunction Visualization

## Goal

Push the game from 8.5 to 10 as a representation of basic quantum principles. v0.3 fixed the two worst credibility issues (classical override, leftover SUPERPOSED fiction). v0.4 closes the remaining gap by:

1. **Proving** the quantum claim live with a CHSH self-test panel — the player can watch the Bell-inequality violation accumulate on screen, rather than just trusting the README.
2. **Visualizing** the probability amplitudes the player is otherwise asked to take on faith — Bell entanglement threads connect partner walls on the minimap, and amplitude bars appear briefly on candidate walls right before the non-zero circuit fires.

## Background: why CHSH

The Bell pairs in the maze use the `|Φ+⟩` state measured in the computational basis on both sides. That gives perfect correlation (both walls SOLID or both OPEN), which the player sees as the purple-flash partner collapse. But perfect correlation alone doesn't *prove* non-locality — a classical strategy ("flip a shared coin, both follow the same rule") trivially gives perfect correlation too.

To prove non-locality, you need the **CHSH (Clauser–Horne–Shimony–Holt) inequality test**. The test measures correlations across four different angle-pair combinations and computes a single number `S`. Any classical hidden-variable theory obeys `|S| ≤ 2`. Quantum mechanics, using a Bell pair measured at the right angles, reaches `|S| ≈ 2.828` (Tsirelson's bound). Real experiments with noise land around `S ≈ 2.6–2.7`. The act of crossing 2 is the empirical proof.

The CHSH panel runs this experiment continuously in the background while the player plays, accumulates `S`, and renders a live readout. After a couple of minutes the panel converges to `S > 2`, **on the player's own screen, with their own quantum runs**.

## Design Decisions

| # | Question | Decision |
|---|---|---|
| 1 | CHSH cadence? | Slow trickle: one trial every ~2 seconds in the background, independent of maze measurements. |
| 2 | Wavefunction visualization scope? | Both Bell partner threads (persistent on minimap) AND amplitude bars on candidate walls (transient at measurement). |
| 3 | Does CHSH share the maze's Bell pairs? | No. CHSH runs an independent stream of fresh Bell pairs with randomized angles, sent via a new endpoint. The maze's own Bell pairs continue to use fixed angles and demonstrate correlation only. |

## CHSH Panel

### Backend: new endpoint `type: "chsh"`

Request body:
```json
{ "type": "chsh", "alice_angle_deg": 0.0, "bob_angle_deg": 22.5 }
```

The backend builds the `|Φ+⟩` Bell state, then rotates Alice's qubit by `-2 * alice_angle_deg` (so the measurement effectively occurs along the requested axis) and Bob's qubit by `-2 * bob_angle_deg`, then measures both in the computational basis.

Response:
```json
{ "a": 0, "b": 1 }
```

Implementation in Qiskit: prepare `|Φ+⟩` (`H` on qubit 0, `CNOT` 0→1), then apply `RY(-2*alice_angle_rad)` on qubit 0 and `RY(-2*bob_angle_rad)` on qubit 1, then measure both. The factor of 2 is because `RY(θ)` rotates the state by `θ/2` on the Bloch sphere; we want the measurement axis itself to rotate by `alice_angle_deg`, so we apply `RY(-2*alice_angle_deg)`.

### Frontend: CHSH trial loop

`startChshLoop()` runs in the background after game start:

1. Pick `x ∈ {0, 1}` and `y ∈ {0, 1}` uniformly at random — these are the "color cards" for Alice and Bob.
2. Pick Alice's angle: `0°` if `x=0`, `45°` if `x=1`.
3. Pick Bob's angle: `22.5°` if `y=0`, `-22.5°` if `y=1`.
4. POST to `/collapse` with `type: "chsh"`, await `{a, b}`.
5. Determine win: if `x === 1 && y === 1`, win if `a !== b`. Otherwise win if `a === b`.
6. Update running tallies: `trials`, `wins`, and a running estimate of `S` (see below).
7. Sleep ~2 seconds, repeat.

Loop stops on game over (preserves last value visible) and restarts on game start.

### Computing S

`S` is defined as a combination of correlation expectations:

```
E(x, y) = P(a = b | x, y) - P(a ≠ b | x, y) = 2 * P(a = b | x, y) - 1
S = E(0,0) + E(0,1) + E(1,0) - E(1,1)
```

Implementation: maintain four counters `n_xy` and `n_same_xy` for each `(x, y)` pair. Update on every trial. Compute `S` whenever the panel renders.

### Panel UI

Docked below the minimap, ~180px wide:

```
┌─ CHSH SELF-TEST ────────────────┐
│  trials: 487                    │
│  S = 2.71                       │
│  ▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮▮│▮ │
│  0     classical max: 2.0   2.83│
│                                 │
│  ★ Non-locality confirmed       │
└─────────────────────────────────┘
```

- Title row.
- Trial counter.
- Big `S` number.
- A horizontal bar from `0` to `2.828` (Tsirelson's bound), with a tick at `2.0` (classical max) and a fill bar at the current `S` value.
- Status line: while `S < 2`, says "Accumulating measurements…". Once `S ≥ 2.0`, switches to "★ Non-locality confirmed".

Color: bar fills amber while `S < 2`, cyan when `S ≥ 2`.

### Edge cases

- First few trials: `S` is wildly noisy. Display "Accumulating measurements…" until `trials ≥ 30`.
- Server unreachable: catch the error, pause the loop, retry after 10 seconds. Don't crash the game.

## Wavefunction Visualization

### Part A: Bell partner threads on the minimap

For each currently-`ENTANGLED` wall, draw a thin translucent line from the wall's center to its partner's center on the minimap.

- Color: light purple `rgba(179, 102, 255, 0.35)`, line width 1px, dashed `[2, 3]`.
- Drawn beneath everything else (so player dot, flashes, etc. stay on top).
- Disappears the moment the pair collapses — once `state !== 'ENTANGLED'`, the thread is gone.
- Implementation: extend `drawMini` to iterate walls, find ENTANGLED ones, draw the lines once per pair (track which we've drawn to avoid duplicates).

This makes the non-local connection **visible before it fires**, which the original game's amber-everywhere rendering hid. When a Bell measurement triggers, the player has already seen "these two walls were linked," then sees the partner pulse purple, and the thread vanishes.

### Part B: Amplitude bars on candidate walls at measurement

Inside `processNonzeroCircuit`, after marking candidates pending but **before** the await on the server:

1. Compute `marginal = (2 ** (k - 1)) / (2 ** k - 1)`.
2. For each candidate wall, add a `wavefuncBar` overlay to a new global array `amplitudeBars`. Each entry: `{ wallId, marginal, t: 0, lifetime: 600 }`.
3. The main render loop draws these as small horizontal bars adjacent to each candidate wall — a thin cyan bar `marginal * 100` percent filled, with the percentage shown as text (e.g. `57%`).
4. When the server responds and the wall transitions to OPEN or SOLID, the bar's lifetime is forced to expire (`t = lifetime`), and it fades out over the last 200ms.

Rendering: bars are drawn only on the main first-person view (not the minimap, where they'd be too small). Position: floating in front of the wall surface in the 3D view, with text label.

### Coexistence with existing flashes

The amplitude bars use a new array (`amplitudeBars`) parallel to `flashes`. They don't compete with Bell pulse / teleport / repair flashes. The `frame` loop advances both.

## Acceptance Criteria

1. Backend test: 2000 simulated CHSH trials with the standard angles produce `S = 2.83 ± 0.1`. Anything below `2.6` indicates a circuit bug.
2. Frontend: after 60 seconds of normal play, the CHSH panel displays `trials ≥ 30` and `S > 2.0`. The status text reads "Non-locality confirmed".
3. Bell pair threads visible on the minimap from game start until each pair collapses. No threads persist after collapse.
4. Amplitude bars appear on candidate walls at every cell entry where `k ≥ 1`, briefly visible (~600ms), with correct `2^(k-1) / (2^k - 1)` values.
5. No regressions: the v0.3 acceptance criteria (no classical override, orphan rate ≤ 25%, exit row distribution, etc.) still pass.

## Risk / Open Concerns

- **CHSH server load.** ~30 calls/minute on top of maze measurements. AerSimulator handles this without trouble; just verify the game doesn't feel sluggish.
- **Amplitude bar rendering in first-person view.** The 3D rendering already uses a painter's algorithm with nested frames. Inserting text labels on walls requires care to render at the right depth without z-fighting. Fallback: render bars only on the closest visible wall (depth 0 or 1).
- **CHSH loop timing across game over.** The loop must cleanly stop on `gameOver` and on `restart`. Use an incrementing `chshSessionId` — the loop checks each iteration and self-cancels if the session changes.
